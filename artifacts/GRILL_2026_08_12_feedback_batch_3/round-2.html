1. Your answers 2 and 3 contradict — which wins?

Answer 2 said AVIF is generated only by npm run build; answer 3 said dev and build must emit identical output. One of them has to give.

2. Removing interaction relations also removes a typo guard — keep it?

assertKnownNames currently fails the build when a card's rule text quotes a card or archetype name that does not exist anywhere. It only runs because interaction parsing runs.

3. The warm build is 0.66 s — do you still want a --scope flag?

You answered "skip the split, add a scope flag". The measurement landed after: the entire content build minus encoding is 0.66 s, so the flag's whole addressable budget is under a second.

4. Docs rename — what does the build do with root-level .md files?

Folder-derived grouping needs every doc inside a numbered folder, but 8 docs sit loose at the root of docs/ right now, and you are doing the moves yourself.

5. What URL do the numbered folders produce?

You are numbering folders and files for ordering. Those numbers either stay in the URL forever or get stripped — and stripping means every existing docs URL changes exactly once.

6. Blog rail shape — it becomes the only index

With the post list gone from /blog/, the rail is the only place a visitor sees every post. You asked for full-width titles and numeric dates; this decides the structure around them.

7. How do we prove the cache never serves stale bytes?

A caching bug does not crash — it silently publishes yesterday's card image. This is the one risk the whole item-1 fix introduces.
