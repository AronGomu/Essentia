00Scope & constraints

The site stays a static build: no backend, no accounts, no database. Every feature below is either generated at build time from repository sources or executed in the visitor's browser. That constraint shapes the search index, the PDF generator, and the print builder more than anything else.

Hard constraints

  • Output is output: 'static', deployed to GitHub Pages under a configurable BASE_PATH, trailingSlash: 'always'.
  • CSP is locked to default-src 'none' with script-src 'self' and img-src 'self' data:. No CDNs, no external fonts, no third-party analytics, no remote PDF service.
  • MSE folder projects stay the only source of card fields. The website never writes card data.
  • Locked packages are immutable; published pages must keep resolving old versions.

Design rules for the new surfaces

  • Card facts always come from the generated catalog — never re-typed into prose, docs, or deck files.
  • Decklists, docs, and posts are authored as repository files, validated at build, and fail the build when they reference an unknown card.
  • Every visitor-built collection (print basket, deck sandbox) lives in localStorage plus a shareable URL — never on a server.
  • Heavy JavaScript (search index, PDF library) is lazy-loaded only on the routes that need it.

What already exists and gets reused

  • scripts/build-content.mjs — validated package reader, image derivative generator, catalog emitter (schema v3).
  • components/CardHoverPreview.astro + the data-card-preview attribute — the hover preview needed for embedded decklists is already built.
  • lib/mse-markup.ts, lib/markdown.ts — MSE rich-text and Markdown rendering.
  • scripts/check-links.mjs, check-budgets.mjs, check-licenses.mjs, check-rights.mjs, harden-csp.mjs, scan-dist.mjs — the quality gates each new feature must extend rather than bypass.

01Data & build foundation

Six of the seven feature areas need catalog fields that do not exist yet. Build this first; everything after it is UI work on top of a stable contract.

Catalog schema v3 → v4

rework

Extend the generated catalog with the fields the search, deck, print, and docs surfaces query. New per-card fields:

colors: string[]        // parsed from castingCost: {1}{B} → ["B"]
manaValue: number       // numeric, sortable
typeLine: string        // superType + subType, prebuilt for search
types: string[]         // ["Creature","Fiend"] tokenized
supertypes: string[]    // ["Trap","Legendary","Ritual"]
zone: 'main' | 'extra'  // extra = Fusion/Synchro/Xyz/Link
keywords: string[]      // bold invocations extracted from ruleText
archetype: string|null  // authored bucket, see "Archetype provenance"
archetypeRole: 'member'|'support'|'staple'
setId, setName, stage, version, releasedOn   // already present per version
printAsset: { url, width, height, dpi }      // print-resolution render
oracleNormalized: string // lowercased, diacritic-free rules text for search

Keyword extraction reuses the rule already enforced by the linter: bold spans in MSE markup are keyword invocations. The build resolves each against the keyword registry (§02) and fails on an unknown bold phrase — the same closed-taxonomy rule docs/KEYWORDS.md states, now enforced by the site build.

Archetype provenance

rework

Archetype is metadata and is never printed on a card. Today it is inferred from the draft project folder recorded in identities.json (PROJECT_SECTION_GROUP), with a stableId-prefix guess as fallback — implicit and fragile. v4 splits it into two explicit concepts:

  • Membership — derived from the card name via a namePattern on each archetype in sections.json, mirroring the in-game rule ("a card with 'Burning Abyss' in its name") that Descent, Abyssal Curse and Nekroz Recovery actually reference.
  • Bucket — authored per card in identities.json as archetype + role: member | support | staple. This is what carries Tour Guide, Manju, Senju and Preparation of Rites into their archetype pages.

The build asserts role === 'member' exactly when the name pattern matches, so browse buckets can never contradict card text. Folder mapping and prefix fallback are deleted; a card with no authored archetype fails the build. Search exposes a: for the bucket and is:member / is:support for the distinction.

One master render, four tiers

solved

Current renders — in the package and on the site — are 375 × 523 px, because that is what the sevenhalf stylesheet declares and --export-images emits. Roughly 150 DPI: fine on screen, visibly soft printed. The fix is verified: an MSE export template calling write_image_file(card, width:, height:) re-renders at any size — 50 cards at 2480 × 3458 in ~14 s, with genuinely sharp type rather than an upscale.

  1. Ship essentia-print.mse-export-template in the repo, installed into MSE's data dir by the launcher, exporting 1500 × 2092 (600 DPI) into renders_print/. Past that only type gains detail — frame bitmaps are 375 × 523 and source art is 624 × 624.
  2. Derivatives from that master: thumb 240 px (grids, deck rows), display 750 px (card page, hover), zoom 1500 px, print master PNG for PDFs.
  3. Progressive quality: thumb paints first, display/zoom swap in after load — skipped when saveData or a 2G-class connection is reported, with a manual "load high quality" control always available.
  4. Print masters are excluded from page-weight budgets and tracked under their own ceiling. Until masters exist, the PDF generator upscales and stamps a "draft resolution" footer.

02Documentation system

Today the site hand-copies a fraction of the rules into two Astro pages (/rules/, /philosophy/) while the real corpus — design, conversion, zones, summoning, templating, deck building, four keyword modules, four archetype modules — stays in docs/, invisible to visitors. The script sells this as the place players go to decode keywords, so it becomes a first-class section of the site.

Publish docs/ as a documentation site

rework
  • A build step copies docs/**/*.md into an Astro content collection, rewriting relative .md links to site routes and validating every internal anchor (fails the build on a dead link, extending check-links.mjs).
  • Route shape mirrors the existing documentation map: /docs/, /docs/rules/…, /docs/design/…, /docs/keywords/…, /docs/archetypes/burning-abyss/….
  • Left rail = the doc tree from docs/CONTEXT.md. Right rail = existing ChapterSummary component fed by generated headings.
  • /rules/ and /philosophy/ become curated landing pages that link into the corpus instead of duplicating it; duplicated prose is deleted so the docs stay single-source.
  • No per-page edit or source links — docs are for reading. A single GitHub link lives in the site footer for anyone who wants to contribute.

Keyword registry & auto-linking

new

The whole compression bet — heavy keywords instead of paragraphs — only pays off if a keyword is one click from its definition.

  • Build parses the four keyword modules into a registry: { id, term, category, definition, seeAlso[], archetype? }.
  • /keywords/ index with category filters and instant filter box; /keywords/<term>/ detail page with definition, related keywords, rules citations, and every published card that uses it (reverse index from §01).
  • RichText gains a keyword pass: bold invocations in card rules text render as links with a hover/press definition popover — no layout shift, works with keyboard, degrades to a plain link without JS.
  • Search gains kw: (§05) so "show me every card with Detach" is one query.

05Search engine (Scryfall-grade)

The current search palette matches card names only, and lib/query.ts — a parser for q/text/type/rarity/date — is dead code wired to zero pages. Replace both with a real query language, a static index, and a dedicated results page.

Query language

new

A Scryfall-style tokenizer → AST → evaluator in src/lib/search/: bare words match name and rules text, key:value filters, comparison operators : = != < <= > >=, quoted phrases, - negation, OR, and parentheses.

Parser errors are surfaced inline — the failing token underlined, with a suggestion — never a blank result page.

Index and runtime

new
  • Build emits /generated/search-index.json: one compact record per card version with short keys. At 50 cards it is a few dozen KB; at 2,000 cards still well under 1 MB and gzip-friendly.
  • Search runs entirely client-side in a Svelte island, fetched on first use (connect-src 'self' already permits it), cached in memory. No index request on pages that never search.
  • Query state lives in the URL: /search/?q=t:fiend+mv%3C%3D1&view=grid&order=mv — shareable, back-button correct, no client-side router needed.
  • The ⌘K palette stays as the quick name jump, gains "Search full syntax for …" as its last row, handing the query to /search/.

06Decklists

Decks are authored by hand in the repository — no editor, no builder, display only. Two presentation modes share one data source.

Deck data format

new

Today release.json holds a flat array of card ids per deck: no quantities, no main/side split, no lands — while docs/rules/DECKLISTS_ALPHA_0.1.md has all three. One authored file per deck, validated against the catalog at build time: 

// website/content/decks/lota-alpha-burning-abyss.json
{
  "slug": "lota-alpha-burning-abyss",
  "name": "Burning Abyss — Alpha 0.1 starter",
  "archetype": "burning-abyss",
  "package": "LOTA-0001-Alpha_0.1",
  "author": "aron",
  "updated": "2026-08-01",
  "colors": ["B"],
  "summary": "Fiend swarm into Xyz value. The deck that started the project.",
  "sections": [
    { "id": "main",  "label": "Main Deck",
      "entries": [ { "card": "burning-abyss-graff", "qty": 2 },
                   { "card": "burning-abyss-cir",   "qty": 2 },
                   { "land": "swamp",               "qty": 14 } ] },
    { "id": "extra", "label": "Extra Deck (Sideboard)",
      "entries": [ { "card": "burning-abyss-dante", "qty": 2 } ] },
    { "id": "flex",  "label": "Flex slots",
      "entries": [ { "card": "maxx-c", "qty": 1 } ] }
  ],
  "notes": "Descent once per turn keeps the board honest."
}

Build-time validation: unknown card or land id fails; a card outside the referenced package fails; section totals are compared against the deck-building rules (40 main / 10 extra / 2-copy limit) as a warning, not a hard failure, so experimental lists stay publishable.

release.json.decks stays the authoritative membership record; deck files must be a subset of it. Presentation data (quantities, sections, notes) lives only in the deck file — no duplication of card fields anywhere.

A published deck never changes. It ships with a site update, carries that date, and stays frozen. A revision is a new file with a new slug plus supersedes / supersededBy links; the old page keeps working. CI (check-immutable-decks.mjs) fails a content-hash change on an already-published deck.

Lands live in content/lands.json and are referenced as { "land": "swamp", "qty": 14 }. Scryfall's Alpha-set basic art is downloaded and vendored into public/generated/lands/ (CSP forbids hotlinking) and registered in asset-rights.json under the third-party clause. The schema carries kind, colors and types from day one, so adding duals later is a data change with no code change — cards and lands flow through one DeckEntry type everywhere.

Mode 1 — embedded list (MTGGoldfish style)

new

<Decklist id="…" mode="compact" /> for posts and docs: quantity + card name only, grouped by section, in tight columns. Hovering a name pops the card render — reusing the existing data-card-preview / CardHoverPreview mechanism, so this costs almost nothing to build.

  • Zero-JS baseline: names are links to card pages; the preview is progressive enhancement. On touch, tap opens the card page; long-press shows the preview.
  • Header row: deck name, archetype chip, card count, link to the full page, and a small Print proxies action.
  • Optional sections="main,extra" to embed only part of a list mid-article.

Mode 2 — full decklist page

new

/decks/ index (filter by archetype, package, colors) and /decks/<slug>/ detail:

  • Visual mode (card renders in a grid, stacked by quantity) and text mode, toggled and remembered.
  • Breakdowns: mana curve, color split, type distribution, main vs extra counts, land count — all computed from the catalog, never authored.
  • Section columns grouped by card type inside each section, matching how deck sites present lists.
  • Author notes, related post, source package, and a "cards in this deck also appear in" cross-link.
  • Export bar: Proxy PDF, TXT (2 Cir line format, MTG-style), CSV, JSON, Copy to clipboard, Permalink. All generated in-browser; no server round-trip.
  • Open in print builder hands the whole list to §08 with quantities preserved.

07Proxy print & PDF engine

One engine, invoked from everywhere: any collection of { cardId, copies } becomes a print-ready PDF in the browser. This is the feature the script promises most directly.

Engine

new
  • src/lib/print/ — layout maths (page size, card box, grid, margins, cut marks) shared with the existing Python tool's geometry so screen and repo output agree.
  • PDF built with pdf-lib (MIT), bundled locally and lazy-imported on first use only. It clears the CSP: no network, no eval. check-licenses.mjs already gates the licence.
  • Images fetched same-origin from /generated/print/…, embedded as PNG at 63 × 88 mm, 3 × 3 per A4 or Letter page.
  • Generation runs in a Web Worker with a progress bar (a 100-card sheet is a few seconds of image decoding); harden-csp.mjs gains worker-src 'self'. Download via object URL and a download anchor.
  • Deterministic output: same input list → byte-identical PDF, so a printed sheet can be reproduced later.

Entry points

new

  • Gallery / archetype / section pages — multi-select then Add selected.

08Print builder page — no accounts

/print/

new

A single page where a visitor assembles any set of cards and prints it — a proxy basket, not a deck editor, and explicitly not an account.

┌──────────────── /print/ ────────────────────────────────┐ │ Add cards [ search box: t:fiend a:burning-abyss ] │ │ Quick add [ Deck ▾ ] [ Release ▾ ] [ Archetype ▾ ] │ ├─────────────────────────┬───────────────────────────────┤ │ Basket (46 cards) │ Options │ │ 2 × Burning Abyss Cir │ Page A4 ▾ Cut marks ▾ │ │ 2 × Graff − + │ Copies 1 ▾ Ruler ☑ │ │ … │ Pages: 6 · ~8 MB │ │ [Clear] [Copy list] │ [ Preview ] [ Download PDF ] │ └─────────────────────────┴───────────────────────────────┘
  • State — localStorage['essentia.print.v1'], so the basket survives reloads and browsing. A persistent header badge shows the count from any page.
  • Sharing without accounts — the basket encodes into the URL (/print/?list=…, ids + quantities, compressed and base64url'd) so a list can be pasted to a friend. Long lists fall back to the paste-a-text-list import.
  • Import — paste a text decklist (2 Cir per line); names resolve through the same normalizer the search uses, with an unmatched-lines report the visitor can fix inline.
  • Export — PDF (§07), TXT, JSON; plus Save as deck file which emits a ready-to-commit deck JSON for anyone opening a pull request.
  • Print stylesheet — @media print fallback so the basket page itself prints usable card sheets if PDF generation is unavailable.

/decks/mine/ — saved decklists, still no account

new

Visitors keep as many decklists as they want, stored only in their own browser. Separate from published deck files, but the same format and the same rendering components.

  • Library — every saved deck with name, count, archetype, updated date, and actions: open, edit, duplicate, rename, delete, export, print. Plus New deck.
  • Editor — /decks/mine/<id>/: add cards through the full search syntax, quantity steppers, sections (main / extra / flex, more addable), notes, live curve and counts, and the deck-building rules shown as non-blocking warnings.
  • Storage — essentia.v1.decks with a versioned schema and migration function; QuotaExceededError is reported with an actionable message, and the page states plainly that decks live only in this browser.
  • Portability — export/import JSON round-trips with the published deck format, so a local deck can be exported and submitted as a pull request unchanged; share links use the same URL encoding as the print basket.
