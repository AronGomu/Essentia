Navigation model

Left rail — one surface, two modes

Navigation.svelte, prop mode. Catalog on every page but the reading ones: one flat list, one entry per section in authored order (Non-archetype first, then the archetypes), each with its published count and, for archetypes, a wash of its own accent. Reading on /docs/… and /blog/…: docs use folder-derived disclosure groups; blog uses one flat newest-first list with numeric dates below full-width titles. Blog's rail is its index while /blog/ renders the latest post. There is no second in-page rail; the article body takes the freed width. See shell chrome, ADR 0028 and docs/ADR/proposed/0043-blog-landing-is-the-latest-post.md.

Rail toggle — one square, bottom-right

A single .rail-toggle button, the last child of <nav id="desktop-catalog">: a 2.25rem square pinned to the rail's bottom-right corner, the same size expanded or collapsed. Collapsed is a strip, not a disappearance: html[data-catalog='collapsed'] sets --sidebar: 3.25rem, hides every rail child except the toggle, and never translates the rail off screen. State persists at essentia.v1.catalog-rail. Below 64rem the rail is replaced by the modal drawer, which always shows the catalog.

Header — full width, above the rail

The header spans the whole viewport and paints above the rail, which starts at its bottom border. Order: brand, catalog hamburger (≤64rem), breadcrumb, then Cards → deploy-base home, Learn about Essentia → /docs/, Blog → /blog/, Decks → /decks/, then Find. All four utility links remain inline through 400px; full labels shorten at 64rem and Find squares off at 56rem. Compact budget: 344.5px of 368px available. No popover. See ADR 0027 and ADR 0029.

Back to top

BackToTop.astro on every page but 404.html, bottom-right, hidden until the visitor has scrolled. Behaviour lives in src/lib/back-to-top.ts.

Breadcrumb — one component

Breadcrumb.astro, passed by every page except /. Ancestors collapse under 44rem, leaving the current page label.

Footer — links then licence

Licence & attribution, card updates, card feed, GitHub. The licence sentence sits beneath them as one small line.

Hover preview

One overlay per page, driven by data-card-preview and data-card-keywords on any card link. Shows the enlarged render plus one ruling box per Essentia keyword. Suppressed on coarse pointers.

Find

FindPalette.svelte over src/lib/find.ts: cards, docs, posts and decks, grouped and filterable. The name-scoring function in src/lib/search.ts also feeds the deck editor's add-card box.

Content pipeline

npm run build is one deterministic, offline chain. No step calls a network service.

Authored inputs, all data files: docs/**/*.md and blog/*.md (bodies), docs/keywords/{id}.md (one file per keyword), website/content/sections.json, website/content/section-intros/{slug}.md (one per section), folder and filename prefixes under docs/ (docs order and grouping), website/content/reading-order.json (blog order and grouping), plus identities.json, art-provenance.json, asset-rights.json, color-overrides.json and explanations/.

1 · Registries

identity.mjs loads sections.json + identities.json, compiles archetype name patterns, validates hero art and provenance, resolves each card's section. section-intros.mjs loads one markdown intro per section — a missing, extra or unknown-slug file fails the build.

↓
2 · Keywords

keywords.mjs reads one lower-case file per keyword from docs/keywords/{id}.md: front matter carries term, category, origin, owning doc, preview and reminder; the body is the published ruling. UPPER_CASE files in that directory stay module docs. Adding a file publishes a keyword with no code change. preview without reminder, or an unknown bold phrase in card text, fails the build.

↓
3 · Packages

packages.mjs walks cards_mse/{01_alpha,02_beta,03_release}, parses MSE fields, derives colours, types, zone and keywords, and hashes sources.

↓
4 · Images

images.mjs derives the thumb and display tiers plus the print master with sharp. Hero art is committed, never derived here.

↓
5 · Docs & posts

docs.mjs and blog.mjs load repo Markdown. Both store renderer-matching H2-H4 metadata. Reading pages expose H2 links through ChapterSummary.astro; native fragments need no client JS. Docs groups/routes derive from the folder tree. Posts sort newest first. See ADR 0020, ADR 0041 and ADR 0043.

↓
6 · Catalog

orchestrator.mjs selects the current version per card, builds sections, updates and releases, and writes src/generated/catalog.ts plus the rights inventory.

↓
7 · Render & gate

Astro builds static HTML, harden-csp.mjs replaces 'unsafe-inline' with per-file hashes, then the dist gates run.

Build gates

scan-dist

No symlink, no unexpected extension, no local path, no private key, no source map, no embedded image metadata, no surviving 'unsafe-inline'.

check-404

dist/404.html is a zero-delay noindex redirect to the base, and never regains the not-found page.

check-chrome

Every page carries four ordered header links; every non-home page carries a breadcrumb; every page but 404.html carries Back to top. Reading pages carry the reading shell plus matching desktop/mobile nav. Home hero, gallery, licence and keyword-reminder contracts remain gated.

check-links

Every internal href and src in every built page resolves to a real file.

check-budgets

JS total ≤ 350 KiB, HTML ≤ 500 KiB per page, image ≤ 3 MiB each, print masters ≤ 400 MiB total.

check-rights

Every published render is covered by an owner-approved rights record before a public artifact ships.

Rules the architecture enforces

MSE is the only card source

The website never writes card data. Anything archetype-, deck- or presentation-related lives in website/content/ — JSON registries and authored markdown — or, for keyword rulings, in docs/keywords/.

Membership mirrors the game

A card belongs to an archetype when its printed name says so. Support cards join a section only through an explicit linked: true.

Closed keyword taxonomy

Every bold phrase on a card must resolve to a registered keyword with a ruling, an origin and an owning doc. Unknown phrases fail the build.

Zero-JS baseline

Docs, blog, card, archetype and release pages are fully readable without script. /decks/ is the single documented exception.

Locked CSP

default-src 'none' with hashed inline content. Any new capability must be bundled locally; harden-csp.mjs is the only place the policy changes.

Fail loudly

Every build step validates its inputs and calls fail() on anything unknown. No silent fallback, no unclassified bucket.
