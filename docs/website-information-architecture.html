Navigation model

Left rail — the catalog

Navigation.svelte. Non-archetype group plus one entry per archetype, each with its published count. Collapses to a modal drawer under 58rem.

Header — three destinations

Breadcrumb (left), brand, then Learn about Essentia → /docs/, Blog → /blog/, Decks → /decks/, then the search palette. Identical on every page.

Breadcrumb — one component

Breadcrumb.astro, passed by every page except /. Ancestors collapse under 44rem, leaving the current page label.

Footer — links then licence

Licence & attribution, card updates, card feed, GitHub. The licence sentence sits beneath them as one small line.

Hover preview

One overlay per page, driven by data-card-preview and data-card-keywords on any card link. Shows the enlarged render plus one ruling box per Essentia keyword. Suppressed on coarse pointers.

Search

SearchPalette.svelte, name-scored over the whole catalog. Same scoring function feeds the deck editor's add-card box.

Content pipeline

npm run build is one deterministic, offline chain. No step calls a network service.

1 · Registries

identity.mjs loads sections.json + identities.json, compiles archetype name patterns, validates hero art and provenance, resolves each card's section.

↓
2 · Keywords

keywords.mjs loads the closed registry — term, category, archetype, definition, origin, owning doc. An unknown bold phrase in card text fails the build.

↓
3 · Packages

packages.mjs walks cards_mse/{01_alpha,02_beta,03_release}, parses MSE fields, derives colours, types, zone and keywords, and hashes sources.

↓
4 · Images

images.mjs derives the thumb and display tiers plus the print master with sharp. Hero art is committed, never derived here.

↓
5 · Docs & posts

docs.mjs and blog.mjs load repo Markdown, rewrite internal links to site routes, and fail on an unpublished target.

↓
6 · Catalog

orchestrator.mjs selects the current version per card, builds sections, updates and releases, and writes src/generated/catalog.ts plus the rights inventory.

↓
7 · Render & gate

Astro builds static HTML, harden-csp.mjs replaces 'unsafe-inline' with per-file hashes, then the dist gates run.

Build gates

scan-dist

No symlink, no unexpected extension, no local path, no private key, no source map, no embedded image metadata, no surviving 'unsafe-inline'.

check-404

dist/404.html is a zero-delay noindex redirect to the base, and never regains the not-found page.

check-chrome

Every page carries the three header links and a breadcrumb; the home hero keeps its copy, art and CTA; galleries carry no date groups; the licence line sits under the footer links.

check-links

Every internal href and src in every built page resolves to a real file.

check-budgets

JS total ≤ 350 KiB, HTML ≤ 500 KiB per page, image ≤ 3 MiB each, print masters ≤ 400 MiB total.

check-rights

Every published render is covered by an owner-approved rights record before a public artifact ships.

Rules the architecture enforces

MSE is the only card source

The website never writes card data. Anything archetype-, deck- or presentation-related lives in website/content/*.json.

Membership mirrors the game

A card belongs to an archetype when its printed name says so. Support cards join a section only through an explicit linked: true.

Closed keyword taxonomy

Every bold phrase on a card must resolve to a registered keyword with a ruling, an origin and an owning doc. Unknown phrases fail the build.

Zero-JS baseline

Docs, blog, card, archetype and release pages are fully readable without script. /decks/ is the single documented exception.

Locked CSP

default-src 'none' with hashed inline content. Any new capability must be bundled locally; harden-csp.mjs is the only place the policy changes.

Fail loudly

Every build step validates its inputs and calls fail() on anything unknown. No silent fallback, no unclassified bucket.
