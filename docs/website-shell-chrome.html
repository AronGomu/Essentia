Shell chrome

The header, the catalog rail, the mobile drawer, and the rules that keep them from fighting each other. Companion to information architecture.

Geometry

.site-header — full viewport width · sticky top:0 · z-index: calc(var(--z-sticky) + 2) · min-height: var(--header)
.desktop-catalog
inset: var(--header) auto 0 0
width: var(--sidebar)
⟨
main, .site-footer — margin-left: var(--sidebar)
  • The header is a menubar, not a column neighbour: it spans the viewport and outranks the rail.
  • The rail begins at the header's bottom border. --header: 4.5rem, --sidebar: 17rem (3.25rem collapsed).
  • The content column, not the header, is what clears the rail.
  • Below 64rem the rail is display: none and the modal drawer takes over; main and the footer lose their inset.
Do not add transform, filter, backdrop-filter or will-change to .site-header. The <Navigation> island renders inside it, and the rail inside that island is position: fixed. Any of those properties would make the header the rail's containing block and pin the rail to the header instead of the viewport. A unit test asserts none of them is declared, at every measured width. See ADR 0027.

Why the island lives inside the header

The hamburger used to be position: fixed; top: 0.8rem; left: 1rem, floating over the brand, with the header reserving padding-left: 8.8rem to clear it. Moving <Navigation client:load> inside <header>, directly after the brand, makes it an ordinary flex item. Astro ships astro-island { display: contents }, so the island wrapper generates no box and is invisible to the flex row — <FindPalette> has always worked this way.

Compact header, ≤44rem

Labels hide, names persist

Text ships as <span class="label-full">, with a <span class="label-short"> where a shorter word exists (“Learn about Essentia” → “Learn”). CSS swaps which one is display: none; an explicit aria-label on the control keeps the accessible name viewport-independent.

Four links, always inline

<div class="utility-menu">, a plain flex row at every width. No island, no script, no popover — Cards, Learn, Blog and Decks stay in that order down to 400px. Cards uses the deploy-base homepage URL.

Never remove the strings

scripts/check-chrome.mjs fails the build when a built page's .utility-nav block lacks Cards, >Learn about Essentia<, >Blog< or >Decks<, when their order changes, or when the page lacks >Find</span>. Shorten with CSS, never with markup.

One row at 400px

400px is the narrowest supported width. shared/header-row.mjs holds the budget; scripts/check-header-row.mjs warns and exits 0; an inline page script console.warns a real wrap. The red bar comes from the Playwright single-row test, not from either warning. See ADR 0029.

Catalog rail

One flat list

Catalog mode renders one <ul> over sections, in the order authored in website/content/sections.json — Non-archetype first, then the archetypes. No group heading, no disclosure. The mobile drawer renders the same list.

Tint by kind

Each archetype <li> gets --nav-tint: var(--{accent}) — set through the CSSOM by Navigation.svelte's onMount pass, not as a style attribute. The built site runs a hashed style-src with no 'unsafe-hashes', so a per-element style="" is blocked and logs a CSP error; li.style.setProperty() is not policed. non-archetype is not an archetype and stays untinted — its authored relic accent is a page theme, not a section identity.

  • rest: color-mix(in oklch, var(--nav-tint, transparent) 14%, transparent)
  • hover / focus / current: color-mix(in oklch, var(--nav-tint, var(--sleeve)) 32%, var(--sleeve))
  • hydration-gated: with JavaScript off the tint never lands and both fallbacks above apply — the rail's pre-tint look.

One square toggle

A single 2.25rem .rail-toggle, the last child of <nav id="desktop-catalog">, align-self: flex-end and margin-top: auto. Same footprint in the 17rem rail and the 3.25rem collapsed strip, so it never moves or resizes when the rail toggles. State: html[data-catalog], persisted at essentia.v1.catalog-rail.

Reading mode

On /docs/…, root docs render as bare links followed by collapsible folder groups. The current page's group opens on arrival; each group's state persists under essentia.v1.docs-group.{group}. Blog groups retain authored headings. The redundant Docs | Blog switcher is gone; header links own that choice. check-chrome.mjs still requires every desktop rail destination in the mobile drawer.
