# ADR 0037 — Markdown images scale through an authored class ladder

- Date: 2026-08-12
- Status: Proposed
- Scope: `website/src/lib/markdown.ts`, `global.css`, docs/blog corpus; page backgrounds provenance
- Review: `ai-artifacts/GRILL_2026_08_12_feedback_batch_2/round-1.html` Q7, Q8

## Context

The docs/blog renderer is a hand-written safe Markdown subset (ADR 0017: no MDX, no new runtime dependencies). It supported links, code, emphasis, lists, tables, quotes, headings, rules — never images. Feedback asked for images plus a percentage scale.

Percentage scale wants `style="width:60%"`. That channel is closed on purpose: `harden-csp.mjs` hashes inline `<script>`/`<style>` blocks and **throws** if `'unsafe-inline'`, `'unsafe-hashes'`, or `'unsafe-eval'` survives, and `scan-dist.mjs` re-checks the built output. `dist/` currently contains zero `style="…"` attributes. CSS `attr()` for non-content properties is not portable across the three browsers the e2e suite runs.

Separately, two archetype page backgrounds are AI-generated by the owner, while `content/art-provenance.json` states "No generative service is used".

## Decision

### D1 — Syntax

`![alt](/path)` and `![alt|N%](/path)`. `N` is a multiple of 5 in 5…100; absent means 100.

### D2 — Scale is a class, not a style

Emit `<img class="md-image md-image-scale-N" …>` against 20 authored rules in `global.css`. CSP-safe, no build step, no preprocessor. The cost is a 5% granularity ladder instead of arbitrary percentages.

### D3 — Site-absolute sources only

Image URLs must start with `/`. External and `data:` sources throw. Reasons: CSP is `img-src 'self' data:`, and remote art carries no rights record. Consequence: the same `.md` read on GitHub will not resolve the image. The website is the publication surface; accepted.

### D4 — Image rule precedes the link rule

`![x](/y)` contains `[x](/y)`. The image rule runs first and parks its whole tag, so the link rule and the emphasis rules never see it. Reversing that order produces `!<a …>x</a>`.

### D5 — Page backgrounds are AI-generated and say so

`public/backgrounds/{burning-abyss,nekroz}.webp` are converted once by a manually-run script (the `make-hero-art.mjs` pattern, never part of `npm run build`), recorded in `content/art-provenance.json`, and the file's `note` is corrected to state that these backdrops are AI-generated by the owner. They are page decoration: `check-rights.mjs` scope is card renders (`release:*` keys) and does not cover them.

## Consequences

- Authors get images and a coarse scale with no new dependency and no CSP weakening.
- An arbitrary percentage (63%) is a hard error, not a silent round. The error names the rule.
- The provenance note stays truthful, which is the only reason it is worth keeping.
- Per-page background urls are injected as one hashed `<style>` block, so archetype pages stay base-path correct under `BASE_PATH=/YGO-x-MTG/`.
