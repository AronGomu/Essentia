Keyword ruling pipeline

Where a keyword's published ruling text comes from, what decides whether it shows in a hover box or as card reminder text, and which gates refuse a broken combination. Companion to docs/KEYWORDS.md (taxonomy) and docs/ADR/proposed/0023-keyword-rulings-in-per-keyword-docs.md (decision).

Source of record

One file per keyword, at docs/keywords/{id}.md. Case decides what a file in that directory is:

lower-case kebab — keyword data

mill-n.md, on-enter.md, abyssal-curse.md. Read by the content build. Never published as a doc page.

UPPER_CASE — module doc

ACTIONS.md, EVENTS.md, ABILITIES.md, COSTS_AND_PROCEDURES.md. Narrates the taxonomy. Published under /docs/keywords/….

File shape

---
term: Mill N
category: action
origin: magic
doc: docs/keywords/ACTIONS.md
preview: true
reminder: true
---

Send N cards from the top of your Deck to the Grave. The quantity is always printed.
KeyRequiredMeaning
idfilenameDerived from the filename stem. Kebab-case.
termyesPrinted invocation, in normalized form (Detach N, not Detach 1). No < or >.
categoryyesaction · event · ability · cost-procedure · archetype
archetypeiff archetypeOwning archetype slug. Present only when category: archetype.
originyesmagic (evergreen, unchanged meaning) or essentia (defined here). Provenance only — it decides nothing on screen.
docyesRepo-relative path to the module that narrates the keyword. Must exist.
previewyesShow the ruling in the gallery hover box.
reminderyesAppend the ruling as (reminder) text after the bold phrase in card rule text.
bodyyesThe ruling. One paragraph, plain text, 20–400 characters, no < or >.

Build pipeline

read

scripts/content/keywords.mjs → loadKeywordRegistry(dir) walks docs/keywords/, keeps lower-case kebab files, parses front matter via keyword-file.mjs, validates every field, returns Map<term, entry>.

↓
extract

extractKeywords(ruleText, registry, source) pulls every <b>…</b> run out of MSE card text, splits composites on and / &, folds numeric parameters to N, and fails the build on an unknown phrase. The taxonomy is closed.

↓
catalog

scripts/content/orchestrator.mjs writes catalog.keywords[] (id, term, category, archetype, definition, origin, doc, preview, reminder) and each card's sorted keywords[] into src/generated/catalog.ts.

↓
render — hover

BaseLayout.astro serialises the preview subset into <script id="keyword-rulings">. CardGallery.astro and the related-cards list fill data-card-keywords from previewKeywordsFor(card). CardHoverPreview.astro joins the two at pointer time.

↓
render — card text

cards/[id].astro passes reminderDefinitions() to RichText; mse-markup.ts → appendReminders() writes <span class="reminder">(…)</span> after each resolved bold phrase.

Gates

Closed taxonomy

extractKeywords() fails the build on any bold phrase with no keyword file. Bold is not decoration; it is an invocation.

preview ⇒ reminder

The loader rejects preview: true with reminder: false. See the note below.

Published HTML

scripts/check-chrome.mjs → reminderIssues() re-reads the built card pages: a bold phrase resolving against that page's ruling map must be followed by a reminder span.

MSE style lint

.script/lint_mse_card_style.py owns the other half: which words must be bold (MSE006, MSE014), which must not (MSE009), and which bold phrases are unknown (MSE004).

Docs corpus

scripts/content/docs.mjs skips lower-case files in docs/keywords/; every other .md under docs/ must appear in reading-order.json or the build fails.

Injection

term and the ruling reject < and >; BaseLayout additionally escapes < to \u003c before writing the JSON block with set:html.

Why preview implies reminder. The page ruling map that CardHoverPreview reads is the preview subset. The published-HTML gate asserts that any bold phrase resolving against that same map carries an inline reminder. A keyword that previews but does not remind would therefore be in the map with nothing to satisfy the gate, and the build would fail on the card page rather than on the bad data. The loader rejects the combination at its source instead.

Authoring

  • Reword a ruling → edit the body of docs/keywords/{id}.md → cd website && npm run content.
  • Add a keyword → create docs/keywords/{new-id}.md with all six front-matter keys → npm run content. No code change.
  • Retire a keyword → delete its file. The build then fails on any card still printing it in bold, which is the point.
  • Change where it shows → flip preview / reminder, respecting the matrix above.
