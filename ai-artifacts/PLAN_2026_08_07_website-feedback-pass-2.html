Headline finding

One parser line blanks half the catalog

packages.mjs::parseFields tests the field-start pattern before the continuation pattern. MSE writes <error-spelling:en_US:/…> back into card text on save. Those colons make an indented continuation line look like a new field key — so rule_text flushes empty and the rest of the card is swallowed. Every Nekroz card, Dante, and most staples: 26 of 50. 

	rule_text:
		<i-auto>(1 - Activated Sorcery Hard)</i-auto> <b>Discard</b> <error-spelling:en_US:/magic.mse-game/…>Brionac</…>; …
                                                              ^ read as a new field key → rule_text = ''
The trap. The naive fix does not build. visualSourceHash is derived from the parsed fields and every render-provenance.json attestation is pinned to it, so correcting the parser yields content: LOTA-0001-Alpha_0.1: stale render/provenance for bagooska. Decision (ADR 0021): keep the old parser verbatim as legacyVisualFields and feed only the hash from it. Verified during planning: build green, 50/50 cards with text, zero unknown keywords.

Decisions frozen here

ADR 0021 — freeze the hash input

Two parsers side by side. legacyVisualFields feeds visualSourceHash only. No re-render, no provenance rewrite, no cards_mse/ edit, Python untouched.

ADR 0020 — reading surfaces

One .reading-shell for docs and blog. Eight named tokens carrying a small chroma — a narrow, written exception to the Neutral Night Rule, scoped to .reading-*.

Decks means both kinds

Published decks are indexed at build time from catalog.releases[].decks. The visitor's own decks are read from localStorage after mount, in their own browser, and sort above the published ones. Local decks never touch a built file — a check-chrome gate fails the build on deck:local: in any page. Both gain anchors: /releases/…/#deck-<id> and /decks/#deck-<id>.

Article vs script

The polished article moves to blog/<date>-<slug>.md. The raw video script and teleprompter stay in content/, which is what content/context.md is for.
