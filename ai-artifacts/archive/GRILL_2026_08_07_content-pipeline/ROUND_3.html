Runtime, resolution, brand and conventions

Your Round 2 answers picked a headless-Chromium renderer, torchaudio forced alignment and a logo-gated build. Scouting those three choices against this machine turned up two hard facts that change what is buildable: the card artwork inside every MSE card is stored at 311 x 228 pixels, and this machine has no pip, so the dependency route the repo documents does not currently work at all. Nineteen questions below. The first two figures are the ones to read before answering anything.

1. How do Python and the ML dependencies actually get installed?

You asked for heavyweight ML deps in the main hashed lock and for the thing to be system agnostic. Neither is currently true: python -m pip does not exist here, and even Pillow, the single pinned dependency, fails to import. So the repo's documented install command works nowhere on this box. Adding torch on top of a broken route makes it worse. Whatever you pick here also fixes the seven existing .script/ modules that import PIL.

2. Where does the Playwright renderer live, and who calls whom?

Playwright is a Node package in website/, with Chromium already cached. The alignment step is Python. The pipeline has to cross that line somewhere, and where you cross it decides how much of the codebase the pipeline can reuse and how many browser downloads you carry.

3. How are frames captured from the browser?

The naive approach is to run CSS animations and screenshot as fast as possible, which produces dropped and duplicated frames and is not reproducible. Since your verification plan is unit tests plus ffprobe assertions, the render needs to be deterministic enough that the same inputs give the same video.

4. What frame rate and encode profile?

Frame rate sets both the render cost and how the push-ins read. Every frame is a browser screenshot, so 60 fps literally doubles the wall clock. The encoder choice trades speed against reproducibility: nvenc output varies with driver version, which would make byte-level assertions impossible.

5. What is the length policy?

Audio duration drives the timeline, but a video is not just the narration: there is lead-in before the first word, and the end card runs past the last one. Shorts now allows 180 seconds, so the practical ceiling is far looser than it was, but a 3-minute card reveal is not the format.

6. Which alignment model, and is the timing stored?

Forced alignment is the only step needing PyTorch. If its output is stored, everyone else can rebuild the video without torch at all, the timings become reviewable and hand-correctable, and the render becomes reproducible even if the model changes. If it is not stored, torch is a permanent hard dependency of every build.

7. What is the audio chain and loudness target?

You will mix narration against a music bed. Platforms normalise loudness on upload, so mastering too hot just gets turned down, and the music has to sit far enough under the voice that captions are not the only way to follow it.

8. What is the scope of the HD artwork backfill?

You committed to backfilling HD art. The scope decides whether this blocks the first video or the whole project. There are 3 HD images today, 50 cards in the current alpha set, and 223 source images in total including drafts that may never ship.

9. By what method is the HD artwork produced?

There is no automated route to higher-resolution source art. The YGOProDeck endpoint the repo uses returns the 624 px tier and exposes nothing larger. ADR 0018 (proposed) already ruled out generative image APIs on the grounds that the pipeline must be deterministic, offline and key-free. No upscaler is installed on this machine, though there is a 16 GB GPU sitting idle.

10. How does the HD art reach the card render, and at what size?

This is the question figure one exists for. The art MSE renders is not read from original_images/. Each .mse-set folder contains its own mse_images/ copy, and those copies are 311 x 228 pixels, exactly the art window at 1x. So the 1500 x 2092 print master is a 4x upscale of a thumbnail, and raising the export template further only magnifies the same thumbnail. The embedded images have to be rebuilt from HD sources first. 1500 x 2092 already gives the textbox zoom more pixels than it needs; the only reason to go higher is if you want to push in tighter than the textbox.

11. What form does the brand mark take?

You decided the pipeline is not built until the mark exists, so this is now on the critical path. The site currently has no logo at all: .brand is a type treatment in the nav and there is no favicon or logo asset in website/public/. The mark has to work at two very different sizes: a persistent corner watermark of maybe 80 px, and an end card at several hundred.

12. Where does the mark live, and which fonts ship with it?

Round 2 settled that Charter plus an OFL sans get vendored. Confirmed: Charter was donated to the X Consortium with unrestricted redistribution, Aptos is Microsoft proprietary. There are currently no font files anywhere in the repo outside MSE/fonts/, and the website declares no @font-face at all, so the site is rendering in fallbacks for most visitors right now. Whatever the pipeline vendors can fix that too.

13. How is the CTA shown on screen?

You said the CTA is spoken, with a YouTube icon and the website URL shown, and viewers sent to the description for links. Using the actual YouTube logo means accepting YouTube's brand guidelines: unmodified, correct colour, minimum clear space, and no implication of endorsement or partnership.

14. Which copy artifacts get written?

Caption limits are 2200 characters almost everywhere, so one caption covers TikTok, Reels and the Instagram feed post. X is the outlier at 280 characters on a free account, which no amount of templating can squeeze a long caption into. YouTube wants a description with actual clickable links, since that is where you are sending viewers.

15. What is the hashtag policy?

Every field the templates could draw on is already in the generated catalog: archetype, colours, rarity, card type, set. So hashtags can be derived deterministically rather than typed, which is also what makes them unit-testable. Instagram caps at 30; current guidance is that far fewer performs better.

16. What is on the static post, and what ratio goes to X?

Round 1 settled on a composed 4:5 graphic plus a bare card PNG as a second slide. 4:5 (1080 x 1350) is the tallest ratio Instagram shows uncropped. On X, a 4:5 image also displays taller in the mobile timeline than 16:9, so the same file may serve both.

17. What is the command surface?

Your original constraint was one terminal command. Existing repo tools are verb-named scripts under .script/ invoked as python .script/<name>.py <subcommand>. Whatever runtime you picked in Q1 changes the prefix, but not the shape.

18. What lives where on disk, and what is committed?

Round 2 settled that outputs go to a gitignored output/ and inputs are a per-card folder keyed by card id. What is still open is the rest: your voice recordings, the override file format, and the music pool. Audio adds up fast, and this repo already carries images, renders and MSE binaries.

19. What fails hard, and what only warns?

You already said the missing print master should fail loudly. Now there is a longer list of things that can be missing or wrong: HD source art, transcript markers, alignment confidence, rules text too long for the textbox pan, missing music, no logo asset. A build that silently produces a soft or broken video is worse than one that refuses.
