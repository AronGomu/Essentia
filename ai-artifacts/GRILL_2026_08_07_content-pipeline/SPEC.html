The settled output of five interview rounds and seventy-four decisions. This is the shared-understanding document: what gets built, with what, to what numbers, in what order. Nothing has been built. Read it, and if it matches what you have in your head, say so and I will start.

02 Runtime and stack

Decided

Pythonuv-managed environment, committed uv.lock. Replaces requirements-dev.lock; the existing Pillow pin migrates one to one.
OrchestrationPython in .script/. Reads cards_mse/ directly through mse_content.load_manifest.
RendererNode script driven by subprocess, reusing the Chromium already cached for @playwright/test 1.61.1.
FramesPage exposes renderFrame(t). No CSS animation. Driver walks frame indices and screenshots each resolved state.
Encodelibx264 CRF 18 preset slow. Not nvenc: byte-identical output is what makes ffprobe assertions meaningful.
Alignmentwav2vec2 base 960h (MIT) driving torchaudio.functional.forced_align.

Verified on this machine

  • uv 0.11.21 installs a managed CPython 3.13.14 on NixOS and runs it. Tested, not assumed.
  • C extension wheels resolve. uv add pillow then import PIL returns 12.3.0.
  • Hashes work. uv export emits --hash=sha256: in the format the current lock already uses.
  • torch 2.13.0 / torchaudio 2.11.0 publish cp313 manylinux wheels. torch is 527 MB.
  • ffmpeg 8.1.2 with libx264, libass, libfreetype, and nvenc available but unused.
  • RTX 5060 Ti, 16 GB, Ryzen 7 7700, 30 GiB RAM, 885 GB free.

Why 527 MB of torch is acceptable

timing.json is committed, so alignment runs once per card on your machine and never during a rebuild. torch is an authoring tool, not a build dependency. Anyone can rebuild every video with no model, no GPU and no torch at all.

03 On disk

One convention amendment required

content/context.md currently documents one dated folder per piece of content. Per-card content is a repeating, id-keyed volume that does not fit that rule, so it gets the content/cards/ namespace and context.md gains a short section saying exactly that. Your existing 2026-08-01-legend-of-alpha-project-introduction/ folder is untouched and the dated rule still governs long-form pieces.

04 The short

Act by act

actwhat happens
1Artwork. HD plate at full width over a blurred, darkened, zoomed copy of itself. Slow push from 1.00 to 1.10 scale, ease-out. Captions and watermark only. No card name — withholding it is what gives act 2 something to reveal.
2Reveal. 0.18 s horizontal directional blur whip, resolving to the card already in place at 82% width. The act 1 artwork stays behind it, blurred and darkened, as the bed.
3Rules. Zoom 1.47x so the textbox fills the width, keeping a sliver of card border visible at the edges. Above roughly 220 characters of plain rules text, slow-pan down the box at a speed derived from the overflow.
endCTA. Card shrinks and retreats upward. Below it: wordmark, official YouTube icon with the channel handle, site URL, and a line reading links in description. Accent-tinted background.

Audio

  • Two-pass loudnorm on the final mix to -14 LUFS integrated, -1 dBTP.
  • Music sidechain-ducked roughly 18 dB under narration.
  • Track selected by archetype from a committed manifest, with a default and a per-card override.

Type and colour

  • Charter for the wordmark, card name and titles. Open Sans heavy for captions, collector number, URL and utility text.
  • Palette from the card's archetype accent token in OKLCH, with the Magic colour identity secondary. No pixel is read.

The graphic

  • post-1.png, 1080x1350. Card at about 78% height on an accent-tinted field over a subtle blurred artwork bed — the same plate as act 1, so post and video read as one piece of work.
  • Card name in Charter above. Collector number and set code small below. Wordmark watermark in a corner.

  • The same 4:5 file goes to X, where it occupies more vertical space than 16:9.

The words

  • caption.txt — hook line naming card and archetype, then the rules text verbatim, then a link line, then hashtags. The verbatim rules text is what makes the archive searchable.
  • caption.short.txt — card name, one-line hook, site link. Fits 280.
  • description.txt — card name and set, full rules text, both links, then a short project explainer.
  • alt.txt — card name, type line, plain rules text.
  • Hashtags: fixed core set plus archetype- and colour-derived, deduplicated, capped at 8, generated from card data.

07 Verification and failure

Tests

  • Golden plan.json fixtures for two or three representative cards, asserted field by field. The highest-value test: any change to timing, geometry or copy shows up as a readable diff with nothing rendered.
  • Pure-function tests for caption chunking, act resolution, geometry, palette and copy templates.
  • Slug cross-check over the real card corpus, asserting the Python port produces exactly the ids the catalog uses.
  • One integration test producing a real short and asserting duration, resolution, frame rate, codec and loudness via ffprobe. Skipped when node or ffmpeg is absent, matching how the existing render tests behave.
  • No pixel comparison. Plain unittest, matching the 19 existing test files.

Failure policy

  • Hard fail: missing HD source art, missing print render, missing transcript or audio, alignment not covering the transcript, model unavailable without --spread, music manifest naming an absent file.
  • Warn: low alignment confidence, rules text long enough to force the pan, fallback act fractions used because markers were absent.
  • --preview downgrades every fatal to a warning. You can always see something; you cannot ship it by accident.

09 Risks I am carrying forward

  • Upscaled art is invented detail. A 1.47x zoom onto a 4x upscale will still be softer than native. This buys a large improvement over 311x228, not true 1920 fidelity.
  • Safe-area numbers are unofficial. Every figure comes from community references; no official Meta or TikTok document was found. Check the first short on a real phone on all three platforms before publishing a run of fifty.
  • LUFS targets for TikTok and Reels are medium-confidence and disputed between -16 and -12. -14 is a compromise that no platform will mangle badly.
  • wav2vec2 base 960h is deprecated as a torchaudio bundle from 2.8. It still loads, but may eventually need loading as raw weights rather than through the bundle API.
  • Rebuilding mse_images/ produces a large diff across 50 committed binaries and changes package-sha256.json, aggregate-manifest.json and render-provenance.json. Legal, but not a small commit.
  • book-of-moon-image.png is 745x1040 — a whole card, not an art crop. It will need special handling or exclusion in the rebuild.
  • The YouTube icon carries obligations. Unmodified, correct colour, minimum clear space, no implication of endorsement.
